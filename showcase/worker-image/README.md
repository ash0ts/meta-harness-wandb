# Pinned worker environment

`uv.lock` is the exact lock from the upstream example's local environment at continuation. `requirements.lock.txt` is exported with `uv export --frozen --offline --no-dev --no-emit-project --format requirements-txt`; all downloads are hash checked. On 2026-11-10, all 62 CPython 3.13 Linux wheels were downloaded and installed offline in the pinned amd64 image. The real-worker Linux smoke completed six jobs and 260 stub calls, then resumed with zero additional calls. Archive verification was tested separately against the actual 127,825,920-byte tar. These are local environment checks; live sandbox isolation and transport require their own receipts.

For prebuilt-image mode, build `Dockerfile` for linux/amd64, run the offline bundle with network disabled, publish the image to the chosen registry, and put its immutable digest in a new campaign manifest. Publishing an image is a separate external action.

For the recommended wheelhouse mode, download the locked **CPython 3.13 linux/amd64 wheels**, not the host Mac's wheels. Package only regular files at `wheels/*.whl`, `requirements.lock.txt` and `SHA256SUMS`. SHA256SUMS must list the requirements file and every wheel using paths relative to the archive root. Record the tar SHA-256, byte count, SHA256SUMS hash and requirements hash in a new manifest. The executor verifies all four before installation and installs with `--no-index --require-hashes`.

After downloading into `wheelhouse/wheels`, run `python package_wheelhouse.py`. It writes a deterministic PAX tar (some wheel basenames exceed USTAR's 100-character limit) and a JSON hash/size receipt. The resulting tar SHA-256 for this lock is `fcd6ba4a2c9a53eed17c64360acb612a3d4d1239ee19ca8727cac8f57b3bfb21`; binaries stay outside Git. Verify the archive with the same `mhforge.bundle.WHEELHOUSE_SNIPPET` used by the worker, then run installation with network disabled. A successful install from the loose wheels does not prove the archive verifier works.

The existing public base-image digest is retained from the design. Live PF6 must prove architecture, Python version, package imports, offline tokenizer loading, egress denial, lifetime enforcement and cleanup. A local dependency lock alone does not establish these platform properties.
